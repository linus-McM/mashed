# Story 4: Repo Context Flow (App.svelte to WorkflowBuilder)

**Priority:** P0-critical
**Domain:** fullstack
**Estimated Complexity:** M
**Depends On:** Story 3
**Status:** done

## Description

Plumb repo context from the app shell into WorkflowBuilder so that workflows are automatically scoped to a specific repo. When the user opens the workflow builder, they either select a repo first (via a picker modal) or the app auto-selects based on context. The selected repo path flows into WorkflowBuilder as a prop, and all API calls (list workflows, save, execute) use it. This eliminates the need for a repo dropdown in ExecutionBar.

## Developer Notes

### Architecture
- **Modify:** `frontend/src/App.svelte` -- add repo selection state, pass as prop to WorkflowBuilder
- **Modify:** `frontend/src/views/WorkflowBuilder.svelte` -- accept `repoPath` prop, use it in all API calls
- **New file:** `frontend/src/components/bmad/RepoPickerModal.svelte` -- modal for selecting a repo before entering the builder
- Uses existing `ListRepoChoices()` binding which returns `[{name, path, branch}]`

### App.svelte Changes

```svelte
<!-- Add state for selected builder repo -->
let builderRepoPath = '';

function openWorkflows() {
  // Show repo picker first, then navigate to workflows
  showRepoPicker = true;
}

function onRepoSelected(e) {
  builderRepoPath = e.detail.path;
  showRepoPicker = false;
  currentView = 'workflows';
}
```

```svelte
<!-- Pass repoPath to WorkflowBuilder -->
{:else if currentView === 'workflows'}
  <WorkflowBuilder repoPath={builderRepoPath} on:back={goBack} />
```

### WorkflowBuilder.svelte Changes


### RepoPickerModal.svelte Design
- Full-screen overlay modal (similar to SpawnAgent modal pattern at `frontend/src/views/SpawnAgent.svelte`)
- Lists repos from `ListRepoChoices()` in a scrollable list
- Each repo item shows: name, branch, path (dimmed)
- Click to select, Escape to cancel (go back to feed)
- Optional: show sprint-status indicator (has/missing YAML file) next to each repo

### Technical Considerations
- The `ListBmadWorkflowsByRepo` TypeScript binding must exist -- it will be auto-generated by Wails from the Go method added in Story 3
- `CreateFromTemplate` signature change from Story 3 means the `useTemplate` handler must pass `repoPath`
- When the builder loads, it should also call `GetSprintStatus(repoPath)` to check if sprint data is available (prepares for Story 5)
- The `terminalRepoPath` variable in WorkflowBuilder should be set from the `repoPath` prop instead of from the execution start event

### Risks & Edge Cases
- User might open workflow builder when no repos are available -- show empty state in picker
- Repo path could contain spaces -- ensure it is passed as-is (no URL encoding)
- If the user had a workflow open and navigates back then re-opens with a different repo, the canvas should reset

### Reference Files
- `frontend/src/App.svelte` -- current view routing and modal patterns
- `frontend/src/views/SpawnAgent.svelte` -- modal pattern to follow
- `frontend/src/views/WorkflowBuilder.svelte` -- all API calls to update
- `frontend/src/components/bmad/ExecutionBar.svelte` -- repo dropdown to eventually remove (Story 6)

## Acceptance Criteria

AC-1: Repo picker shown before workflow builder
- Given the user is on the feed view
- When they click the Workflows button (or Cmd+W)
- Then a repo picker modal appears listing all available repos
- And each repo shows its name and branch

AC-2: Selected repo flows into WorkflowBuilder
- Given the user selects "my-project" from the repo picker
- When the WorkflowBuilder loads
- Then it receives `repoPath="/Users/linus/Development/my-project"` as a prop
- And the listed saved workflows are filtered to that repo

AC-3: Saved workflows are repo-scoped
- Given the user is in WorkflowBuilder with repoPath "/repo-a"
- When they create and save a new workflow
- Then the saved workflow has `repoPath: "/repo-a"` in its definition
- And switching to a different repo does not show this workflow

AC-4: Execution uses repo from prop
- Given a WorkflowBuilder with repoPath set
- When the user starts a workflow execution
- Then the `StartBmadWorkflow` call uses the repoPath from the prop
- And the user does not need to select a repo separately

AC-5: Cancel returns to feed
- Given the repo picker modal is showing
- When the user presses Escape or clicks outside
- Then the modal closes and the user stays on the feed view
