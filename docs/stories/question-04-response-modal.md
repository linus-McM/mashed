# Story 4: Question Response Modal & End-to-End Integration

**Priority:** P0-critical
**Domain:** fullstack
**Estimated Complexity:** M
**Depends On:** Story 2 (question-02-backend-response), Story 3 (question-03-snackbar-stack)
**Status:** ready

## Description

Complete the question-answer loop by adding a response modal that appears when the user clicks a snackbar and navigates to the workflows view. The modal displays the full question text, renders either clickable option buttons (for menu questions) or a textarea (for freeform questions), and calls the `RespondToQuestion` Wails binding to inject the answer back into the tmux session. On success, the question is removed from the global queue. This story also wires up the `pendingQuestion` prop on `WorkflowBuilder.svelte` to auto-open the modal on navigation.

```svelte
  import { X, Send, MessageCircleQuestion } from 'lucide-svelte';
  import { RespondToQuestion } from '../../../wailsjs/go/main/App.js';

  export let question;  // QuestionEvent object

  const dispatch = createEventDispatcher();
  // dispatch('responded')  -- answer sent successfully
  // dispatch('close')      -- user dismissed without answering
  // dispatch('error', { message })  -- send failed

  let answer = '';
  let sending = false;
  let error = '';

  async function submit() { ... }
  function selectOption(option, index) { answer = String(index + 1); submit(); }
</script>
```

**Layout:**
- Overlay: semi-transparent backdrop (`rgba(0,0,0,0.6)` or `color-mix(in srgb, var(--bg-base) 60%, transparent)`), z-index 400
- Modal card: `max-width: 560px`, centered, `var(--surface-2)` background, `border-radius: 8px`
- Header: question icon + "Question from {repoName}" + close X button
- Body:
  - Full question text in a styled blockquote box (`var(--surface-1)` background, left border `var(--accent-green)`)
  - If `question.options.length > 0`: render a vertical list of clickable option buttons (each option is a button styled with `var(--surface-3)` background, hover `var(--surface-4)`)
  - If `question.options.length === 0`: render a `<textarea>` with placeholder "Type your response..." (3 rows, auto-grow)
- Footer: Cancel button (secondary) + Send button (primary, `var(--accent-green)` background)
- Send button disabled when `sending` is true or (freeform mode and `answer` is empty)
- Error state: if `RespondToQuestion` call fails, show error message in red below the textarea

**Submit flow:**
1. Set `sending = true`
2. Call `await RespondToQuestion(question.execId, question.nodeId, answer)`
3. On success: dispatch `'responded'`
4. On error: set `error = err.message`, set `sending = false`

### WorkflowBuilder.svelte Changes

```svelte
export let pendingQuestion = null;

let showQuestionModal = false;
let activeQuestion = null;

$: if (pendingQuestion) {
  activeQuestion = pendingQuestion;
  showQuestionModal = true;
}

function handleQuestionResponded() {
  showQuestionModal = false;
  activeQuestion = null;
  dispatch('question-responded', { nodeId: activeQuestion?.nodeId });
}

function handleQuestionClose() {
  showQuestionModal = false;
  // Don't clear activeQuestion — snackbar stays visible
}
```

Mount at end of template:
```svelte
{#if showQuestionModal && activeQuestion}
  <QuestionResponseModal
    question={activeQuestion}
    on:responded={handleQuestionResponded}
    on:close={handleQuestionClose}
  />
{/if}
```

### App.svelte Changes

Pass `pendingQuestion` prop and handle response:
```svelte
<WorkflowBuilder
  repoPath={builderRepoPath}
  repoBranch={builderRepoBranch}
  pendingQuestion={pendingQuestion}
  on:back={goBack}
  on:question-responded={(e) => {
    pendingQuestion = null;
    questionQueue = questionQueue.filter(q => q.nodeId !== e.detail.nodeId);
  }}
/>
```

### Technical Considerations

- **Wails binding import:** `RespondToQuestion` must be generated by running `wails dev` after Story 2 adds the Go binding. The story assumes the binding exists.
- **Keyboard shortcuts:** Enter key in textarea should NOT submit (it's multiline). Use Ctrl+Enter or Cmd+Enter to submit. Add `on:keydown` handler.
- **Focus management:** Auto-focus the textarea or first option button when modal opens.
- **Transition:** Modal uses `fly` transition (`y: 20, duration: 200`) for entry.
- **Error handling:** Display the error message from the Go backend (e.g., "pane is dead") in a user-friendly way. Include a "Dismiss" action on the error that removes the question from the queue.

### Risks & Edge Cases

- **Process dies while modal is open:** User clicks Send, but the pane is dead. Backend returns error. Modal shows "Process has ended -- this question is no longer pending." Provide a "Dismiss" button to remove from queue.
- **User navigates away before responding:** `pendingQuestion` should be cleared when leaving workflows view. The snackbar remains, so the user can re-navigate.
- **Multiple questions for same repo:** If a second question arrives while modal is open for the first, the modal stays on the current question. The new question appears as a snackbar in the background.
- **Empty textarea submission:** The Send button is disabled when the textarea is empty for freeform questions. For menu questions, clicking an option immediately submits.

## Design Brief

### 1. Layout Composition

The modal follows the established Mashed modal pattern (see `AgentConfigModal.svelte`): full-viewport overlay with a centered card.

**Overlay**:
```
position: fixed; inset: 0;
background: color-mix(in srgb, var(--bg-deepest) 70%, transparent);
z-index: 400;
display: flex; align-items: center; justify-content: center;
```

**z-index 400**: Above snackbar stack (300) and TitleBar (200). This matches the story spec and is forward-compatible. Existing modals use z:100 -- this modal is higher because it must overlay the snackbar stack that triggered it.

**Modal card**: `max-width: 560px; width: calc(100% - var(--sp-2xl) * 2);` -- responsive with 32px side margins on narrow windows.

**Section hierarchy (top to bottom)**:

```
+--------------------------------------------------+
| HEADER: icon + "Question from {repoName}" + [X]  |
|--------------------------------------------------|
| QUESTION BOX: full question text (blockquote)     |
|--------------------------------------------------|
| RESPONSE AREA:                                    |
|   (menu mode)  vertical list of option buttons    |
|   (freeform)   textarea + hint text               |
|--------------------------------------------------|
| ERROR BAR: (conditional) error message + dismiss  |
|--------------------------------------------------|
| FOOTER: [Cancel] ................ [Send/disabled] |
+--------------------------------------------------+
```

**Card structure**:
```css
display: flex;
flex-direction: column;

border-radius: var(--radius-lg);
```

### 4. Interaction Model

**Primary actions**:
- **Freeform mode**: Type in textarea, press Send button or Ctrl/Cmd+Enter
- **Menu mode**: Click an option button (immediately submits, no separate Send step)

**Hover behaviors**:
- Option buttons: bg transitions `var(--bg-elevated)` to `var(--bg-active)`, border to `var(--border-emphasis)`. Duration: `var(--duration-short)`.
- Send button: slight brightness increase via `filter: brightness(1.1)`.
- Cancel button: bg to `var(--bg-elevated)`.
- Close X: color `var(--text-muted)` to `var(--text-dim)`.

**Keyboard navigation**:
- `Tab` cycles: textarea/first-option > Cancel > Send > close X > textarea/first-option
- `Escape`: close modal (dispatch `close` event)
- `Ctrl+Enter` / `Cmd+Enter`: submit (freeform mode only). Plain `Enter` inserts newline.
- In menu mode: option buttons are focusable, `Enter` or `Space` activates the focused option. Arrow keys (`j`/`k` or Up/Down) move focus between options.

**Focus management**:
- On mount: auto-focus textarea (freeform) or first option button (menu)
- Use `bind:this` + `onMount` with `requestAnimationFrame` to ensure focus after transition completes

**State transitions**:
- **Idle**: default state, Send enabled (freeform: only if textarea non-empty)
- **Sending**: `sending = true`. Send button shows a loading indicator (text changes to "Sending..." or a subtle pulse animation). Textarea/options become `pointer-events: none; opacity: 0.6`.
- **Error**: error bar appears below response area with slide transition. Send re-enables. Textarea retains user's input.
- **Success**: modal dispatches `responded` and closes.

**Overlay click**: Clicking the backdrop (outside the modal card) dispatches `close` -- same as Cancel. Use `on:click|self` on the overlay div so clicks inside the card don't bubble.

### 6. Motion Design

| Moment | Transition | Duration | Easing | Detail |
|--------|-----------|----------|--------|--------|
| Overlay fade-in | `fade` | `var(--duration-medium)` (150ms) | `var(--ease-enter)` | Backdrop darkens |
| Card entry | `fly` | 200ms | `cubicOut` | `y: 20` (rises into position from below) |
| Card exit | `fly` | 150ms | `cubicIn` | `y: 20` (sinks away) |
| Error bar entry | `slide` | `var(--duration-medium)` (150ms) | `var(--ease-enter)` | Slides down from above the footer |
| Option hover | CSS `transition` | `var(--duration-short)` (100ms) | `var(--ease-enter)` | Background + border color |
| Send button press | CSS `transform` | 50ms | `ease-out` | `scale(0.97)` |
| Sending state | CSS `opacity` | `var(--duration-short)` | `var(--ease-move)` | Textarea/options fade to 0.6 |

**Transition choreography**: Overlay fades in first (150ms), then card flies up (200ms with ~50ms implicit delay from render timing). The total entry feels like a single 200ms gesture. On exit, card flies down (150ms) and overlay fades out simultaneously.

### 7. Signature Elements

- **Green accent blockquote**: The question text sits in a dark recessed box (`--bg-deepest`) with a 3px `--accent-green` left border. This is the Mashed brand color marking the most important content on screen -- the actual question the agent is asking. The green stripe echoes the notification row pattern from DESIGN.md ("Left accent stripe, 4px, status color").

- **Amber continuity**: The `MessageCircleQuestion` icon in the modal header uses `var(--accent-amber)`, matching the snackbar icon from Story 3. This creates visual continuity -- the amber "question" icon is consistent across the notification and the response surface.

- **Dark-on-green Send button**: The primary CTA uses `var(--accent-green)` background with `var(--bg-deepest)` text. This is the only bright surface in the entire modal, creating an unmistakable focal point. The disabled state dims to `var(--accent-green-dim)`, maintaining the green identity but clearly communicating "not yet."

- **Option number prefixes in mono**: Menu options show their 1-indexed number in `var(--font-mono)` + `var(--text-dim)`, echoing the terminal-influenced aesthetic. The user sees "1. Create new file" -- a pattern familiar from CLI menu prompts, bridging the CLI-to-GUI interaction that BMAD processes represent.

- **No decorative chrome**: The modal has zero decoration beyond the green question stripe and green Send button. Every element is functional. The box-shadow provides depth hierarchy, the border-emphasis separates the modal from the overlay, and the recessed question block creates a clear reading zone. This is the "calm command center" aesthetic from DESIGN.md.

- **Keyboard hint in muted mono**: Below the textarea, "Ctrl+Enter to send" in `var(--font-mono)` `var(--text-label)` `var(--text-muted)`. This tiny detail signals "this is a power-user tool" -- keyboard shortcuts are displayed, not hidden.
